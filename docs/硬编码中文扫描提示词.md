# 扫描提示词：查找项目中未抽取到 strings.xml 的硬编码中文文本

## 任务

扫描 Android 项目 `e:\FlipAccounting-AI`，找出所有**用户可见**的硬编码中文文本，这些文本应该被抽取到 `strings.xml` 中。

## 扫描范围

### 1. 布局 XML 文件（高优先）

扫描 `app/src/main/res/layout/*.xml`，检查以下属性中的中文：
- `android:text="..."` — 显示文本
- `android:hint="..."` — 输入框提示
- `android:contentDescription="..."` — 无障碍描述

**排除条件**（不要报告）：
- 已使用 `@string/` 引用的
- 纯英文/数字/符号（如 "API Key"、"WebDAV"、"CSV"）
- 格式化占位符（如 "%s"、"%d"）

### 2. Kotlin 代码文件（高优先）

扫描 `app/src/main/java/com/taostudio/tapaccounting/**/*.kt`，检查以下场景中的中文字符串：
- `Toast.makeText(...)` 或 `Utils.toast(...)` 的文本参数
- `AlertDialog.Builder(...).setMessage(...)` 或 `.setTitle(...)` 的文本
- `TextView.text = "..."` 的赋值
- `EditText.hint = "..."` 的赋值
- `dialog.setTitle(...)` / `dialog.setMessage(...)` 的文本
- `Utils.snackbar(...)` 的文本

**排除条件**（不要报告）：
- 已使用 `getString(R.string.xxx)` 或 `context.getString(R.string.xxx)` 引用的
- Logger 日志文本（如 `Logger.d(...)` 、`Log.d(...)`）
- 错误异常消息（如 `throw IllegalArgumentException("...")`）
- 注释中的中文
- 变量名/函数名中的中文
- 调试用的临时文本

### 3. strings.xml 自身（低优先）

扫描 `app/src/main/res/values/strings.xml`，检查：
- 超过 30 个字符的设置开关描述文本（建议精简到 15-20 字）
- 重复定义的相似文本

## 输出格式

对每个发现的硬编码中文，输出一行：

```
文件名:行号 | 当前文本 | 建议资源名 | 问题类型
```

**问题类型**：
- `LAYOUT_TEXT` — 布局中的 android:text 硬编码
- `LAYOUT_HINT` — 布局中的 android:hint 硬编码
- `CODE_TOAST` — 代码中的 Toast 文本
- `CODE_DIALOG` — 代码中的 Dialog 文本
- `CODE_TEXT_VIEW` — 代码中的 TextView 赋值
- `STRING_TOO_LONG` — strings.xml 中过长的描述

## 示例输出

```
activity_backup_new.xml:180 | PIN 自动：首次备份将设置 PIN... | backup_pin_auto_desc | LAYOUT_TEXT
BackupActivity.kt:478 | 轻量备份默认不含聊天资源... | backup_lite_hint | CODE_TEXT_VIEW
dialog_edit_ai_rule.xml:42 | 把一句常见口语固定成你的记账偏好... | edit_rule_hint | LAYOUT_TEXT
```

## 注意事项

1. 只报告**真正需要**抽取的文本，不要报告已经是 @string 引用的
2. 不要报告纯英文、数字、URL、代码标识符
3. 不要报告 Logger/Log 日志
4. 不要报告 throw 异常消息
5. 优先报告高频页面（聊天、记账、设置）的硬编码
6. 如果一行中有多个中文字符串，只报告主要的那个
7. 建议的资源名使用 snake_case 命名
