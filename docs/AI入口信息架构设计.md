# FlipAccounting AI 入口信息架构设计

---

## 设计决策

### 决策一："+"永远只做传统手动记账

**不允许用户修改"+"的行为。** 理由：

- "记账"是肌肉记忆，行为必须 100% 可预测
- 给"+"增加配置项意味着用户每次按"+"都需要思考"我现在配置的是什么模式"
- 这是应用的基础设施，不能变成变量

### 决策二：对话页同时支持持久切换 + 单条记账勾选

两种机制并存：

- 顶部模式标签：切换**持久模式**（适合"我要连续记5笔账单"）
- 输入区勾选开关：**仅本条消息**按记账处理（适合"聊着聊着想记一笔"）

### 决策三：先只做工具栏入口，不加底部导航可选标签

- v1 工具栏入口，收集数据后再决定是否需要可选标签
- 底部导航动态管理增加测试复杂度和维护成本，不值得在初期投入

## 一、核心矛盾分析（不仅是"按钮放哪里"）

这个问题的本质不是 UI 布局问题，而是**三种不同"认知模式"在争夺同一个操作入口**：

| 操作 | 用户心智 | 频率 | 耗时 | 容忍度 |
|------|---------|------|------|--------|
| **手动记账** | "我要记一笔"→填入金额类别→完成 | 极高 | 3-10秒 | 零容错，多一步就烦 |
| **AI 对话记账** | "我描述一下这笔消费"→等待 AI 解析→确认 | 中 | 10-30秒 | 低容错，误记不可接受 |
| **Agent 查询/操作** | "我想知道/我想改一下"→对话→等待工具执行 | 低-中 | 30秒-5分钟 | 中性，可探索 |

**核心矛盾一句话**：手动记账是"事务型"操作（transactional），Agent 是"探索型"操作（exploratory）。把探索型入口放在事务型入口旁边，本质上是在加油站门口开了一家咖啡馆——两种节奏完全不兼容。

你试过的四个方案之所以都不满意，是因为每个方案都在试图用**一个入口统一两种截然不同的用户意图**，这本身就是矛盾的。

## 二、"普通记账""AI 对话记账""Agent"是否真的需要三个独立入口？

**答案：不需要三个入口。只需要两个入口 + 一个通道。**

```
入口 A：快速记账（手动记账）          ← 高频、无AI依赖、不可动摇
入口 B：AI 对话（统一入口）           ← 中低频、需AI配置
         └─ 内部通道：模式切换        ← 对话页内部完成
              ├─ 记账模式（AI解析账单）
              └─ Agent 模式（闲聊/查询/工具）
```

**为什么不拆成三个入口：**

1. "AI 对话记账"和"Agent"共享同一底层——都是对话式交互、都用同一个聊天 UI、都调用大模型。它们之间的区别只是"意图偏向"，而意图偏向应该在对话页内部解决，不应该增加一个外部入口。

2. "手动记账"和"AI 对话记账"虽然产出相同（账单），但交互范式完全不同（表单 vs 对话）。强行把它们放在一个入口会让"+"按钮的行为不稳定。

3. 从用户心智来看，真正有效的分组不是"按产出分组"（都是记账），而是**"按交互范式分组"**（表单 vs 对话）。

## 三、四种可实施的信息架构方案

### 方案 A：顶部工具栏入口（推荐方案）

```
首页 Toolbar：[▤ 账本选择]  [🔔] [🤖 AI]
                                           ↑
                                    仅AI已配置时显示
中间 "+" FAB：始终打开传统记账表单
```

- AI 入口：首页顶部工具栏右侧图标
- "`+`" 行为：永不变，总是手动记账
- Agent FAB：**删除**

### 方案 B：底部导航-可选标签

```
底部导航：账单｜统计｜+｜资产｜设置
          （默认无AI标签）
          
AI用户可在设置中开启：
账单｜统计｜+｜资产｜助手｜设置
         或
账单｜统计｜+｜资产｜设置（助手隐藏在设置内）
```

- AI 入口：可选第五个标签（用户手动开启）
- "`+`" 行为：永不变
- Agent FAB：**删除**

### 方案 C：首页分段控件（Segment/Tab）

```
┌──────────────────────────────┐
│  [账单列表]  |  [AI 助手]    │  ← 首页顶部左右切换
├──────────────────────────────┤
│                              │
│   （根据选中标签显示不同内容）  │
│                              │
└──────────────────────────────┘
中间 "+" FAB：根据当前标签改变行为
  - 账单列表 → 手动记账
  - AI 助手 → 打开聊天（Agent模式）
```

### 方案 D：统一对话入口 + 首屏智能默认

```
中间 "+" FAB：打开统一对话页
              └─ 内部根据用户历史行为智能选择默认模式
              └─ 顶部有模式切换按钮

同时保留"快速记账"入口：
  - 下拉刷新区域有一个"快速记一笔"快捷方式
  - 或通知栏常驻快捷方式
```

## 四、各方案详细评估

### 方案 A：顶部工具栏入口 ⭐⭐⭐⭐⭐

| 维度 | 评价 |
|------|------|
| **优点** | ① "`+`" FAB 完全不受影响 ② 不占用底部导航 ③ AI 图标不显眼但对目标用户可发现 ④ 符合 Material Design 次要操作放 Toolbar 的惯例 ⑤ 实现最简单（几乎只是加一个 MenuItem） |
| **缺点** | ① 工具栏图标较小，不如 FAB 显眼 ② Agent 重度用户（每天用5次以上）会觉得图标不够"顺手" |
| **误操作风险** | 几乎为零。"`+`" 永远是手动记账，AI 入口完全不同 |
| **学习成本** | 极低。用户看到机器人/助手图标就能理解 |
| **实现复杂度** | 低 |

**适配用户：**

- 完全不用 AI：图标不显示，完全无感知 ✅
- 只使用 AI 记账：工具栏进入→切换到记账模式→对话记账 ✅
- 经常使用 Agent：工具栏进入→默认 Agent 模式→直接使用 ✅
- 偶尔使用 Agent：图标始终可见但不打扰 ✅

### 方案 B：底部导航-可选标签 ⭐⭐⭐⭐

| 维度 | 评价 |
|------|------|
| **优点** | ① 对重度 AI 用户极其方便（一级入口）② 用户主动选择开启，不骚扰其他人 ③ 导航结构语义清晰 |
| **缺点** | ① 5个标签在 Android 上略拥挤 ② "设置"被挤走或需要调整 ③ 需要额外实现动态导航栏 ④ 标签由用户手动开启，部分轻度 AI 用户可能不知道有这个功能 |
| **误操作风险** | 低。和方案 A 一样，"`+`" 永远不变 |
| **学习成本** | 低-中。用户需要去设置里发现并开启 |
| **实现复杂度** | 中。需要动态管理 BottomNavigationView 的 menu |

**适配用户：**

- 完全不用 AI：无标签，无影响 ✅
- 只使用 AI 记账：开启标签后快速访问 ✅
- 经常使用 Agent：开启标签后极其方便 ✅✅
- 偶尔使用 Agent：可能不知道去设置开启 ⚠️

### 方案 C：首页分段控件 ⭐⭐⭐

| 维度 | 评价 |
|------|------|
| **优点** | ① AI 和账单在同一页面，切换自然 ② 视觉上 AI 被视作"账单的另一种视图"，不喧宾夺主 |
| **缺点** | ① "`+`" 行为根据标签变化，容易让用户困惑 ② 首页复杂度增加 ③ 需要在首页 Fragment 内内嵌聊天或快速跳转逻辑 ④ 如果用户在 [AI 助手] 标签下按"`+`"进入记账模式，但不小心回到 [账单列表]，体验割裂 |
| **误操作风险** | **中**。用户可能在 AI 标签下以为自己在聊天，但"`+`"打开了手动记账 |
| **学习成本** | 中-高。用户需要理解两个标签和"`+`"的关联 |
| **实现复杂度** | 高。需要重构 HomeFragment |

**适配用户：**

- 完全不用 AI：不滑到 AI 标签即可 ✅
- 只使用 AI 记账：可能一直停在 AI 标签，但"`+`"行为不稳定 ⚠️
- 经常使用 Agent：方便 ✅
- 偶尔使用 Agent：分段控件占用首页空间 ⚠️

### 方案 D：统一对话入口 + 首屏智能默认 ⭐⭐

> 这个方案本质上是方案三和方案五的结合，但把"`+`"彻底变成对话入口。

| 维度 | 评价 |
|------|------|
| **优点** | ① 统一性强 ② 技术上一致性好 |
| **缺点** | ① "`+`" 不再打开传统记账→高频用户强烈反对 ② 需要额外的快速记账入口→增加设计复杂度 ③ 智能默认总有猜错的时候 |
| **误操作风险** | **高**。用户按"`+`"想记账，结果打开一个 Agent 对话 |
| **学习成本** | 高。打破了 Android 记账应用"`+`"=添加的惯例 |
| **实现复杂度** | 高 |

**适配用户：**

- 完全不用 AI：彻底不适用 ❌
- 只使用 AI 记账：适合 ✅
- 经常使用 Agent：适合 ✅
- 偶尔使用 Agent："`+`" 行为不确定性高 ❌

## 六、推荐方案：方案 A（工具栏入口）+ 方案 B 的可选项

**核心方案：方案 A 作为默认行为。**

理由：

1. **零破坏性**：对于完全不使用 AI 的用户，应用和现在完全一样。这是最重要的约束。
2. **"`+`"不可侵犯**：手动记账的高频操作路径完全不变。
3. **可渐进增强**：方案 B 的可选标签可以作为后续迭代，让重度用户在设置里开启底部导航标签。
4. **符合平台惯例**：Google Keep、Google Tasks、Google Calendar 等应用都把 AI/助手功能放在工具栏而非 FAB 位置。
5. **扩展性好**：未来 Agent 增加更多工具时，工具栏入口不需要改变。

## 七、信息架构总览

```
                    应用首页
                       │
          ┌────────────┼────────────┐
          │            │            │
     底部导航        工具栏 "+" FAB
          │           🤖AI图标        │
          │         (AI已配置时)      │
    账单|统计|资产|设置            传统记账表单
          │                      (永不变)
          │
     ┌────┴─────────────────────────────┐
     │          ChatActivity             │
     │  ┌──────────┐  ┌──────────┐      │
     │  │ 记账模式  │  │ AI 助手  │      │
     │  │(持久切换) │  │(持久切换) │      │
     │  └──────────┘  └──────────┘      │
     │       ↑             │            │
     │       │      ┌──────┴──────┐     │
     │       │      │☐ 以账单模式 │     │
     │       │      │   发送本条  │     │
     │       │      └─────────────┘     │
     └──────────────────────────────────┘
```

**三个核心原则：**

1. 交互范式决定入口：表单一份、对话一份，不混用
2. 模式是对话页内部的"意图偏向"，不是外部入口
3. 记账永远需要用户确认，模式切换不绕过确认

## 九、对话页面模式系统

### 9.1 两种模式

| | 记账模式 | AI 助手（Agent）模式 |
|---|---|---|
| **标签文字** | `记账` | `AI 助手` |
| **标签颜色** | 绿色 `#4CAF50` | 蓝色 `#2196F3` |
| **图标** | `receipt_long` | `smart_toy` |
| **输入框 placeholder** | `描述这笔账单…` | `询问或操作你的账务…` |
| **发送按钮颜色** | 绿色 | 蓝色 |
| **AI 行为** | 内容强制解析为账单 | 自由对话 + 工具调用 |
| **图片默认处理** | OCR/视觉识别辅助记账 | 作为对话上下文 |

### 9.2 模式切换（持久切换）

```
┌──────────────────────────────────────┐
│  ←      AI 助手      ┌─────────┐    │
│        (会话标题)     │  记账   │    │  ← 当前在"记账模式"
│                      └─────────┘    │
│                      点击后弹出：     │
│                      ┌─────────┐    │
│                      │ 记账    │ ✓  │
│                      │ AI 助手 │    │
│                      └─────────┘    │
├──────────────────────────────────────┤
│  消息列表                            │
│  ...                                 │
├──────────────────────────────────────┤
│  (记账模式专属)                       │
│  ┌──────────────────────────────┐    │
│  │ 📷 [选图]  [_____输入框_____] │➤ │
│  └──────────────────────────────┘    │
└──────────────────────────────────────┘
```

- 点击顶部模式标签 → 弹出下拉选择器（PopupMenu）
- 切换后，顶部标签更新，输入框 placeholder 更新，发送按钮颜色更新
- 切换是持久的：后续所有消息都在新模式，直到再次切换
- **Agent→记账时**：首次出现 Toast 提示 `已切换到记账模式，对话内容将解析为账单`（仅首次提示）
- **记账→Agent 时**：静默切换

### 9.3 单条记账发送（Agent 模式内）

仅在 Agent 模式下显示。

```
┌──────────────────────────────────────┐
│                                      │
│         聊天消息区域                   │
│                                      │
├──────────────────────────────────────┤
│  [🎤] [📎] [______输入框_______] [➤] │
│                                      │
│  ┌─ ☐ 以账单模式处理这条消息 ────┐    │  ← 勾选开关
│  └──────────────────────────────┘    │
└──────────────────────────────────────┘
```

**行为：**

- 勾选后，发送按钮从蓝色变为绿色，输入框 placeholder 变为 `描述这笔账单…`
- 消息发送后，自动取消勾选（单次生效）
- 如果用户先勾选，然后切换到"记账模式"（持久切换），勾选自动取消
- AI 收到带此标记的消息后，按记账模式处理

```
2. 选择完成后返回对话页
```

```
┌──────────────────────────────────────┐
│                                      │
│         聊天消息区域                   │
│                                      │
├──────────────────────────────────────┤

│  │   ✕  │ │   ✕  │ │   ✕  │        │  ← 角标删除按钮
│  └──────┘ └──────┘ └──────┘         │
```

- 缩略图：72dp × 72dp，圆角 8dp，带 1dp 描边
- 每张图片右上角有 ✕ 删除按钮（12dp，白色圆形背景）
- 最多 3 张图片，达到上限后 📎 变灰
- 图片 + 文字一起发送时，作为一个消息组（一张 CompositeMessageCard）

### 10.3 模式对图片的影响

| 模式 | 图片处理 |
|------|---------|
| **记账模式** | 图片用于 OCR + 视觉识别，辅助解析账单金额/类别/时间 |
| **Agent 模式（未勾选记账）** | 图片作为对话上下文，AI 可能描述图片内容、回答相关问题 |
| **Agent 模式（已勾选记账）** | 图片按记账模式处理，用于 OCR + 视觉识别 |

## 十一、记账确认策略

**核心原则：任何 AI 生成的账单都必须经过用户确认才能入库。**

### 11.1 三级确认机制

| 级别 | 场景 | 确认方式 |
|------|------|---------|
| **L1 标准确认** | 记账模式下，单条消息解析出 1 笔账单，AI 高置信度 | 显示账单预览卡片，底部有 [修改] [确认] [取消] 按钮 |
| **L2 加强确认** | Agent 模式下，通过"单条记账勾选"产生的账单 | 同 L1，但账单预览卡片顶部有黄色提示条：`此账单来自 AI 助手对话` |

## 十二、状态管理与会话生命周期

### 12.1 会话创建

```
新会话触发条件：
  - 用户点击工具栏 AI 图标 && 无活跃会话
  - 上次活跃会话超过 24 小时
  - 用户在会话列表中点击"新建会话"
  - 用户通过设置页"打开 AI 助手"进入

新会话默认模式：MODE_AGENT
```

### 12.2 会话恢复

```
返回 + 再次进入时：
  1. 工具栏 AI 图标 → 检查 SharedPreferences 中的 activeConversationId
  2. 如果 activeConversationId 存在 && lastActivityTime < 24h：
     → 恢复该会话，包括：
       - 完整消息历史（从 DB 加载）
       - 用户离开时的模式（记账/Agent）
       - 输入框草稿（如果有未发送的文字）
       - 未删除的图片预览（会话级的临时文件）
  3. 如果 activeConversationId 不存在或超时：
     → 创建新会话，mode = MODE_AGENT

会话归档条件：
  - 超过 24 小时未活跃 → 自动标记为已归档
  - 用户手动在会话列表中"删除" → 软删除
```

### 12.3 返回键行为

```
ChatActivity 中按返回键：
  - 如果有键盘弹起 → 收起键盘
  - 如果无键盘 && 当前会话有消息 → 保存状态，finish()
  - 如果无键盘 && 当前会话无任何消息 → 销毁会话，finish()

MainActivity 中按返回键：
  - 行为不变（现有逻辑）
```

### 12.4 未完成记账提醒

```
如果用户：
  1. 在记账模式下输入了内容
  2. AI 返回了账单预览
  3. 用户未"确认"就退出了

→ 在 SharedPreferences 中记录 pendingBillConversationId
→ 首页 AI 图标显示橙色角标
→ 用户下次进入该会话时：
  - 消息列表底部显示未确认的账单预览卡片
  - 卡片上标注"待确认"状态
  - 用户可继续[确认]/[修改]/[取消]
```

## 十七、风险与缓解

| 风险 | 可能性 | 缓解措施 |
|------|--------|---------|
| 重度 Agent 用户觉得工具栏图标不够方便 | 中 | v1 收集使用数据，如果日均 >10 次打开，v2 增加底部导航可选标签 |
| 用户不知道工具栏有 AI 图标 | 低 | 首次配置 AI 后显示 Tooltip 引导（`TooltipCompat`）；设置页有"打开 AI 助手"入口 |
| Agent 模式中误触"单条记账勾选" | 低 | 勾选不会立即触发任何操作，仅改变发送模式；且账单仍需确认 |
| 切换记账模式后忘记切回来，后续消息被误解析为账单 | 中 | 记账模式下每次 AI 返回账单预览（带确认），不会静默创建；且模式标签始终可见 |

## 十八、一句话总结

> **"+" 做它唯一该做的事——手动记账。所有对话式 AI 交互统一走 Toolbar 入口。对话页内部用持久模式 + 单条勾选来区分意图。任何 AI 生成的账单，必须经过用户确认才能入库。**
