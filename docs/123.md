下面我先给结论：**我不建议把 Agent 做成右下悬浮按钮，也不建议放进底部导航，更不建议让模型完全自动判断。**
最稳的方向是：**普通记账保持绝对主入口；AI 对话记账和 Agent 共用一个“AI 对话页”，但通过明确模式区分；Agent 入口作为二级但稳定入口存在。**

Android/Material 交互上也支持这个判断：FAB 适合承载应用中“最主要、最常用、单一聚焦”的主操作，因此你的中间“+”更应该继续服务“记账”而不是和 Agent 竞争；底部导航更适合顶级目的地，如果 Agent 不是所有用户的一级任务，就不适合长期占据底部导航；而“记账/助手”这种二选一状态，可以用分段按钮或类似模式切换控件表达。([Android Developers][1])

---

# 1. 这个问题的核心矛盾

真正的问题不是“Agent 按钮放哪”，而是 **三类用户意图被放进了同一个聊天形态里**：

| 用户意图           | 是否高频 |        是否有副作用 |      是否需要强确认 |          是否适合自动判断 |
| -------------- | ---: | ------------: | -----------: | ----------------: |
| 普通手动记账         |   极高 |             是 |      用户填写后保存 |               不需要 |
| AI 对话记账        |  高/中 |             是 |     需要确认账单草稿 |           不适合完全自动 |
| Agent 查询/闲聊/导航 |  中/低 | 查询无副作用，操作有副作用 | 修改/删除/创建需要确认 | 可以理解意图，但不能直接执行副作用 |

所以核心矛盾是：

**记账是高频、低容错、副作用操作；Agent 是低频/中频、高扩展、跨页面能力。两者都可以用聊天界面，但不能共用模糊入口和模糊语义。**

你现在纠结入口，是因为你试图让一个入口同时承担：

1. 高频记账入口；
2. AI 记账入口；
3. Agent 总入口；
4. 图片/语音/文本多模态入口；
5. 工具调用入口；
6. 后续扩展入口。

这会导致每一种方案都不舒服。

正确拆法应该是：

**入口按使用频率分层，页面按交互形态复用，发送前按模式明确语义，副作用操作必须确认。**

---

# 2. 三个功能是否需要三个独立入口？

我的判断是：**不需要三个独立一级入口，但需要三个清晰的“意图入口/状态”。**

更具体地说：

| 功能      |       是否需要独立入口 | 建议                                 |
| ------- | -------------: | ---------------------------------- |
| 普通手动记账  |    需要，且必须最高优先级 | 中间“+”单击继续进入普通记账                    |
| AI 对话记账 | 需要入口，但不一定是一级导航 | 从记账页、+ 的辅助入口、AI 对话页切换进入            |
| Agent   | 需要稳定入口，但不应抢主入口 | 放在首页/主页面顶部操作区或“更多”中，不放 FAB，不放底部主导航 |

也就是说，不要做成：

> 普通记账入口 / AI 记账入口 / Agent 入口
> 三个并列一级入口

而是做成：

> 主入口：记账
> 次入口：AI 助手
> 对话页内：记账模式 / 助手模式
> Agent 模式下：允许“本条按账单处理”

# 3. 可实施的信息架构方案

## 方案 A：普通记账主入口 + 顶部 AI 助手入口 + 统一对话页模式切换【推荐】

### 架构

底部导航仍然保持记账产品结构：

> 账单｜统计｜+｜资产｜我的/设置

中间“+”：

> 单击：普通记账
> 长按或在记账页内：显示 AI 记账入口

Agent 入口：

> 首页/账单页顶部右侧放一个轻量入口：“助手”或图标按钮
> 统计页、资产页也可以有上下文入口：“问助手”
> 设置页中提供 AI 配置入口

统一对话页：

> 顶部标题：AI 助手
> 下方分段切换：记账｜助手
> 输入框根据模式改变提示文案和发送按钮

### 优点

* 普通记账路径不变，最高频用户不受影响。
* Agent 有稳定入口，但不会抢“+”的核心地位。
* AI 对话记账和 Agent 共用技术页面，开发可复用。
* 模式明确，降低误记账风险。
* 后续 Agent 工具增加时，不需要改主导航。

### 缺点

* 需要设计一个清晰的对话页模式切换。
* Agent 发现性不如底部导航强。
* AI 记账用户可能需要学习“AI 记账入口在哪里”。

### 误操作风险

低。因为：

* “+”仍然是记账；
* Agent 不自动记账；
* 对话页有明确模式；
* 创建账单前显示草稿确认。

### 学习成本

中低。用户只需要理解：

> 普通记账点 +
> 想用 AI 点助手
> 在对话页选择“记账”或“助手”

### 实现复杂度

中。需要：

* 对话页支持两种模式；
* 入口来源决定默认模式；
* 消息发送前带上 mode；
* 账单创建前统一走确认卡片。

---

## 方案 B：Agent 作为底部导航一级页面

底部导航：

> 账单｜统计｜+｜资产｜助手

### 优点

* Agent 入口最清晰。
* 重度 Agent 用户访问成本最低。
* 产品 AI 感强，有利于突出差异化。

### 缺点

* 对不用 AI 的用户很打扰。
* 牺牲原来的设置/我的位置。
* 应用会从“记账工具”变成“AI 助手工具”。
* 如果 Agent 早期能力不稳定，会放大用户失望。

### 误操作风险

中。用户进入 Agent 后，如果边界不清，仍可能误以为所有输入都会记账。

### 学习成本

低。因为入口非常明显。

### 实现复杂度

中低。导航清晰，但产品定位风险高。

### 适合场景

只有当你的长期战略是：

> AI Agent 是应用的核心卖点，且大部分用户都会使用

否则不建议。

---

## 方案 C：中间“+”展开为添加方式菜单

点击“+”后弹出 Bottom Sheet：

> 手动记账
> AI 记账
> AI 助手

Bottom Sheet 是 Android/Material 中常见的临时操作承载方式，适合放补充操作，但不适合让用户每次高频动作都先选择一次。([Android Developers][2])

### 优点

* 所有创建/AI 入口集中在一个地方。
* 首次发现性强。
* 开发逻辑比较直接。

### 缺点

* 高频普通记账每次多一步。
* “+”含义变模糊。
* 选项越来越多后会膨胀。
* 记住上次选择又会造成不可预测。

### 误操作风险

中。用户可能误点 AI 助手或 AI 记账。

### 学习成本

中。用户需要理解三个入口差异。

### 实现复杂度

低到中。

### 可优化版本

不要单击就展开。可以改成：

> 单击 +：手动记账
> 长按 +：展开添加方式
> 手动记账页顶部提供“AI 记账”

这样它会接近方案 A。

---

## 方案 D：统一聊天入口为主，“+”直接进入对话页

中间“+”点击后直接进入统一对话页，默认“记账模式”。

对话页内可切换：

> 记账｜助手

传统手动记账变成对话页中的一个按钮：

> 手动填写

### 优点

* AI 记账体验非常突出。
* 对“只用 AI 记账”的用户友好。
* 记账和 Agent 的技术界面高度统一。

### 缺点

* 明显牺牲传统记账。
* 不用 AI 的用户被迫进入 AI 场景。
* “+”不再等于快速记账，而是进入聊天。
* 如果 AI 未配置，主入口体验会断裂。

### 误操作风险

中高。因为用户可能不知道当前输入会不会生成账单。

### 学习成本

中高。尤其对传统记账用户。

### 实现复杂度

中。

### 适合场景

适合 AI-first 记账产品，不适合你当前约束。

---

## 方案 E：Agent 放进“我的/设置/更多”，不出现在主界面

入口：

> 我的｜AI 助手
> 设置｜AI 功能
> 账单页空状态/引导卡片偶尔露出

### 优点

* 完全不打扰普通用户。
* 主界面干净。
* AI 未成熟时风险最小。

### 缺点

* Agent 发现性太弱。
* 重度用户访问成本高。
* Agent 明明是重要能力，却像隐藏功能。
* 后续工具增加后入口承载不足。

### 误操作风险

低。

### 学习成本

低，但用户可能根本不知道有 Agent。

### 实现复杂度

低。

### 适合场景

适合作为 AI 功能早期灰度方案，不适合作为长期主方案。

| 用户类型             | 最需要什么      | 最怕什么         | 推荐方案表现                   |
| ---------------- | ---------- | ------------ | ------------------------ |
| 完全不用 AI 的用户      | + 快速手动记账   | 被 AI 打扰、入口变化 | 方案 A 最好，+ 不变             |
| 只使用 AI 记账的用户     | 快速进入 AI 记账 | 每次切模式、找不到入口  | 方案 A 可接受，需要在记账页给明显 AI 入口 |
| 经常使用 Agent 的用户   | 稳定入口、可连续对话 | Agent 藏太深    | 方案 A 较好，顶部助手入口稳定         |
| 偶尔使用 Agent 的普通用户 | 需要时能找到     | AI 占据主界面     | 方案 A 最平衡                 |

# 5. 我最推荐的方案

## 推荐：方案 A 的增强版

即：

> **普通记账主入口不变；AI 对话页统一承载 AI 记账和 Agent；Agent 入口放在主页面顶部操作区；对话页用明确模式切换；所有记账创建先生成草稿再确认。**

它比其他方案更合适的原因是：

1. **保护最高频路径**
   中间“+”仍然是普通记账，不让不用 AI 的用户付出成本。

2. **Agent 有存在感，但不喧宾夺主**
   顶部“助手”入口稳定存在，但视觉权重低于中间“+”。

3. **不依赖模型自动路由**
   发送请求时前端明确传递模式：`bookkeeping` 或 `agent`。

4. **能支持后续扩展**
   Agent 后续增加查询、导航、设置、批量操作，都在 Agent 模式内扩展，不污染主导航。

5. **副作用风险可控**
   AI 记账只生成草稿；Agent 修改/删除/创建账单必须二次确认。

6. **符合 Android 习惯**
   主操作用 FAB/中间 +，辅助操作用顶部 action、Bottom Sheet、模式切换、确认弹窗/确认卡片。

# 6. 推荐方案的详细交互流程

## 6.1 首页入口

首页/账单页结构建议：

底部导航：

> 账单｜统计｜+｜资产｜我的

顶部右侧：

> 搜索图标
> AI 助手图标 / “助手”

不建议用“Agent”作为用户可见名称。对普通用户来说，“Agent”太技术化。

建议命名：

> 助手
> AI 助手
> 问助手

如果空间允许，首页顶部可以是：

> 标题：账单
> 右侧：搜索｜助手

---

## 6.2 中间“+”按钮行为

### 单击 +

直接进入普通手动记账页。

不要弹菜单，不要先问用户选择方式。

### 长按 +

可以弹出快捷 Bottom Sheet：

> 手动记账
> AI 记账
> 扫票据/传图片
> 语音记账

但这只是增强入口，不是主流程。

### 普通记账页内

在手动记账页顶部或底部提供轻量入口：

> 试试 AI 记账

例如：

> 顶部右侧文字按钮：AI 记账
> 或表单上方小卡片：不会填？用 AI 描述这笔消费

这样“只用 AI 记账”的用户也能逐渐形成路径：

> * → AI 记账

但普通用户仍然是：

> * → 手动填写 → 保存

---

## 6.3 Agent 入口

Agent 不放 FAB，不放底部导航。

建议放三类入口：

### 稳定入口

首页/账单页顶部右侧：

> 助手

点击进入统一 AI 对话页，默认模式为：

> 助手模式

### 上下文入口

统计页：

> 问助手
> 例如：帮我分析这个月为什么花得多

资产页：

> 问助手
> 例如：查询我的资产余额

账单详情页：

> 让助手处理
> 例如：修改分类、拆分账单、删除账单

### 设置入口

我的/设置页：

> AI 助手设置
> 模型配置
> 工具权限
> 记账确认方式

---

## 6.4 对话页模式切换

对话页顶部：

标题：

> AI 助手

标题下方使用分段切换：

> 记账｜助手

Material 3 的 segmented button 本身就适合少量互斥选项选择。([Android Developers][3])

### 记账模式

视觉状态：

> 当前模式：记账
> 提示：发送的内容会被解析为账单，保存前会让你确认

输入框 placeholder：

> 说说这笔消费，例如：中午麦当劳 38 元

发送按钮文案：

> 解析

发送后：

> AI 返回“账单草稿卡片”

卡片内展示：

> 金额
> 类型：支出/收入/转账
> 分类
> 账户
> 商家/对象
> 时间
> 备注
> 置信提示

卡片底部按钮：

> 保存账单
> 修改
> 取消

### 助手模式

视觉状态：

> 当前模式：助手
> 提示：可以查询、分析、修改数据；涉及保存或删除前会让你确认

输入框 placeholder：

> 问我账单、统计、资产，或让我帮你操作

发送按钮：

> 发送

如果用户在助手模式下想记账，提供一个一条消息级别的开关：

> 本条按账单处理

点击后，输入框上方出现状态条：

> 本条将解析为账单

发送按钮变为：

> 解析账单

发送完成后自动恢复助手模式。

---

## 6.5 模式是持续模式还是只影响下一条？

建议采用：

> 顶部“记账 / 助手”是持续模式
> 助手模式里的“本条按账单处理”是一次性模式

原因：

* 只用 AI 记账的人，可以一直停留在记账模式；
* 经常用 Agent 的人，可以一直停留在助手模式；
* 偶尔在 Agent 里记一笔账，不需要切换整个会话状态；
* 避免用户不知道下一条消息会怎么处理。

---

## 6.6 图片选择和图文一起发送

输入区建议结构：

1. 左侧：附件按钮；
2. 中间：文本输入框；
3. 右侧：语音 / 发送按钮；
4. 输入框上方：附件预览区。

选择图片后不要立即发送。

应显示：

> 已添加 1 张图片

图片缩略图旁边提供删除按钮。

用户可以继续输入文字，例如：

> 这是昨天晚上的超市小票，帮我记到招商银行卡

最终一起发送。

### 在记账模式下

图片默认按账单相关材料处理。

提示：

> 图片和文字会一起用于解析账单

### 在助手模式下

图片默认只是普通图片上下文，不自动记账。

如果用户要记账，需要点：

> 本条按账单处理

或者切换到：

> 记账模式

---

## 6.7 未配置 AI 时的处理

普通记账完全不受影响。

### 首页

如果 AI 未配置：

* 不要让中间“+”失效；
* 不要弹大面积 AI 引导；
* 顶部“助手”可以显示，但点击后进入配置说明页；
* 也可以在设置完成前隐藏顶部助手入口，只在设置页露出。

我更建议：

> 顶部助手入口保留，但弱化。点击后显示配置页。

配置页文案：

> 开启 AI 助手后，你可以用文字、语音或图片记账，也可以查询账单、统计和资产。
> 普通记账不受影响。

按钮：

> 去配置
> 先不用

### 在 + 进入手动记账时

不要打断。

可以在手动记账页角落显示：

> AI 记账未开启

但不要弹窗。

---

## 6.8 记账前的确认策略

原则：

> AI 永远不要直接创建账单，先生成账单草稿。

### AI 记账模式

流程：

> 用户发送内容 → AI 解析 → 返回账单草稿 → 用户确认保存

草稿卡片按钮：

> 保存
> 编辑后保存
> 放弃

### Agent 创建账单

如果 Agent 识别到需要创建账单：

> 先回复“我整理成了这笔账单，请确认”

然后展示账单草稿卡片。

### Agent 修改账单

例如用户说：

> 把昨天那笔麦当劳改成餐饮

Agent 应先找到候选账单，展示确认卡：

> 将修改以下账单
> 麦当劳 38 元，昨天 12:30
> 分类：快餐 → 餐饮

按钮：

> 确认修改
> 取消

### Agent 删除账单

删除是高风险操作，必须确认。

确认文案：

> 删除后可在回收站恢复，是否删除这笔账单？

按钮：

> 删除
> 取消

Material 对话框本身也强调确认类操作需要用户明确选择，且操作数量应保持克制，这适合用在删除、修改设置等高风险场景。([Material Design][4])

---

## 6.9 返回和再次进入时如何恢复状态

建议采用“入口决定默认模式 + 会话保留状态”的混合策略。

### 从顶部“助手”进入

默认：

> 助手模式

如果用户上次在助手入口进入后切到了记账模式，短时间内返回再进入，可以恢复原状态。

但如果隔天重新打开，建议仍默认：

> 助手模式

### 从“AI 记账”入口进入

默认：

> 记账模式

### 从普通“+”进入

永远进入：

> 手动记账

* 从统计页进，返回统计页；
* 从资产页进，返回资产页；
* 从手动记账页跳转 AI 记账，返回手动记账页或账单页，按你的现有栈设计确定。

# 8. 哪些现有设计应该删除，哪些可以保留

## 应该删除

### 1. 右下角 Agent 悬浮按钮

原因：

* 和中间“+”争抢主操作；
* 在资产页和新增资产冲突；
* 容易像外挂功能；
* 状态变化时消失会破坏稳定性。

### 2. Agent 底部导航一级入口

除非你决定产品转型为 AI-first，否则不建议。

### 3. 点击“+”后每次都选择三种功能

这会伤害最高频普通记账。

### 4. 完全依赖模型自动判断记账/闲聊/查询

尤其图片场景风险很高。

### 5. “记住上次 + 行为”的模糊方案

例如上次用了 AI 记账，下次点 + 就进入 AI。这个会让用户失去确定性。

## 可以保留

### 1. 统一聊天页面

可以保留，但必须加明确模式。

### 2. 对话页内切换“记账 / 助手”

这是合理方向。

### 3. 中间“+”

必须保留为普通记账主入口。

### 4. Agent 工具能力

保留，但所有副作用操作需要确认。

### 5. 图片 + 文字一起发送

保留，而且应该成为 AI 记账和 Agent 的共同输入能力。

下面是一份可以直接给 Android 开发人员看的产品规格草案。

# Android 记账应用 AI 记账与 AI 助手信息架构产品规格

## 1. 目标

在不破坏普通记账高频路径的前提下，引入 AI 对话记账和 AI 助手能力。

核心原则：

1. 普通手动记账仍然是最高优先级入口。
2. AI 助手不占用底部一级导航。
3. AI 对话记账和 AI 助手共用一个对话页面。
4. 对话页面必须明确展示当前模式。
5. 记账、修改、删除等有副作用操作必须经过用户确认。
6. 图片、语音、文字均可作为对话输入。
7. 用户选择图片后，可以继续输入文字，再一起发送。
8. 未配置 AI 时，不影响普通记账。

---

## 2. 信息架构

底部导航保持为：

账单｜统计｜+｜资产｜我的

其中：

* “+”为普通手动记账主入口。
* “助手”不进入底部导航。
* AI 助手入口放在主要页面顶部操作区或上下文操作区。
* 设置页中提供 AI 配置入口。

---

## 3. 首页 / 账单页入口

### 3.1 顶部栏

账单页顶部右侧增加轻量入口：

* 文案：助手
* 或图标：AI 助手图标
* 点击后进入 AI 对话页
* 默认模式：助手模式

### 3.2 底部中间“+”

单击行为：

* 直接进入普通手动记账页

不得出现：

* 每次点击 + 都弹出功能选择
* 根据上次选择改变 + 的默认行为
* 点击 + 直接进入 AI 对话页

### 3.3 长按“+”可选增强

长按 + 可弹出快捷操作面板，包含：

1. 手动记账
2. AI 记账
3. 语音记账
4. 上传图片记账

该面板不是必需主流程。普通用户单击 + 仍然直接进入手动记账。

---

## 4. 普通手动记账页

普通手动记账页保持现有表单流程。

可增加轻量 AI 入口：

* 入口文案：AI 记账
* 位置：页面顶部右侧，或表单上方小卡片
* 点击后进入 AI 对话页
* 默认模式：记账模式

AI 未配置时，点击该入口进入 AI 配置引导页。

---

## 5. AI 对话页

### 5.1 页面标题

标题：

AI 助手

### 5.2 模式切换

标题下方展示二选一模式切换：

记账｜助手

要求：

* 当前模式必须有明确选中态。
* 切换模式后，输入框提示文案和发送按钮文案同步变化。
* 模式切换不应清空已输入文字和已选择附件。
* 切换到记账模式时，提示用户“发送内容会被解析为账单”。
* 切换到助手模式时，提示用户“涉及修改前会让你确认”。

### 5.3 记账模式

记账模式用于 AI 对话记账。

页面提示：

当前为记账模式，发送内容会被解析为账单，保存前会让你确认。

输入框 placeholder：

说说这笔消费，例如：中午麦当劳 38 元

发送按钮文案：

解析

发送逻辑：

* 前端发送 message mode = bookkeeping。
* 后端/模型必须按账单解析处理。
* 返回结果不得直接创建账单。
* 必须返回账单草稿卡片。

账单草稿卡片字段：

1. 类型：支出 / 收入 / 转账
2. 金额
3. 分类
4. 账户
5. 商家 / 对象
6. 时间
7. 备注
8. 附件
9. 置信提示，可选

卡片操作：

* 保存账单
* 编辑
* 放弃

点击“保存账单”后才创建账单。

### 5.4 助手模式

助手模式用于闲聊、查询、分析、页面导航和工具调用。

页面提示：

当前为助手模式，可以查询、分析和操作数据。涉及修改前会让你确认。

输入框 placeholder：

问我账单、统计或资产

发送按钮文案：

发送

发送逻辑：

* 前端发送 message mode = agent。
* 图片默认作为普通图片上下文，不得默认按账单处理。
* 查询类工具可直接执行。
* 页面导航类工具可直接执行，必要时给出提示。
* 创建、修改、删除账单等有副作用工具必须先展示确认卡片。
* 修改设置类工具必须先展示确认卡片。

### 5.5 助手模式下的“本条按账单处理”

在助手模式中，输入框上方或附件区附近提供一条消息级别开关：

本条按账单处理

点击后：

* 显示状态条：本条将解析为账单
* 发送按钮文案变为：解析账单
* 本次发送 message mode = bookkeeping_once
* 发送完成后自动恢复助手模式
* 不改变顶部模式切换的选中项，或发送后恢复助手模式选中态

该功能用于用户在助手模式中临时记一笔账。

## 6. 图片、文字、语音输入

### 6.1 图片选择

点击附件按钮后可选择图片。

选择图片后：

* 不自动发送
* 在输入框上方显示缩略图
* 显示已添加图片数量
* 每张图片可删除
* 用户可以继续输入文字
* 图片和文字一起发送

### 6.2 记账模式下图片处理

提示：

图片将和文字一起用于解析账单

发送时：

* 图片 + 文本一起进入账单解析流程
* 返回账单草稿
* 不直接保存账单

### 6.3 助手模式下图片处理

提示：

图片将作为对话内容发送

发送时：

* 图片默认作为普通上下文
* 不自动记账
* 用户开启“本条按账单处理”后，才按账单解析

### 6.4 语音输入

语音输入转文字后进入当前模式。

记账模式：

* 转文字后按账单解析

助手模式：

* 转文字后作为普通助手消息

用户发送前应可以看到或编辑识别结果。

删除：

1. 右下角 Agent 悬浮按钮。
2. Agent 底部导航入口。
3. 点击 + 后每次弹出三选一功能菜单。
4. 模型自动判断记账/闲聊/查询的默认路由。
5. 根据上次选择改变 + 默认行为的方案。

2. 统一 AI 对话页。
3. 对话页内记账 / 助手模式切换。
4. 图片、文字、语音多模态输入。
5. Agent 查询和工具调用能力。
6. 所有副作用操作前的确认机制。

## 11. 埋点建议

需要记录以下事件：

1. 点击中间 +
2. 进入手动记账页
3. 点击顶部助手入口
4. 点击 AI 记账入口
5. AI 对话页模式切换
6. 记账模式发送消息
7. 助手模式发送消息
8. 助手模式点击“本条按账单处理”
9. 选择图片
10. 图片 + 文字一起发送
11. 生成账单草稿
12. 保存账单草稿
13. 编辑账单草稿
14. 放弃账单草稿
15. Agent 工具调用
16. Agent 工具确认
17. Agent 工具取消
18. 未配置 AI 时点击助手入口
19. AI 配置完成
20. AI 配置取消

核心观察指标：

1. 普通 + 到保存账单的转化率是否下降。
2. AI 记账入口使用率。
3. 助手入口使用率。
4. 账单草稿保存率。
5. 草稿编辑率。
6. 草稿放弃率。
7. Agent 工具确认率。
8. Agent 工具取消率。
9. 用户是否频繁误切换模式。
10. 未配置 AI 用户是否被打扰。

---

## 12. 验收标准

1. 不配置 AI 时，普通记账完整可用。
2. 点击中间 + 必须直接进入普通手动记账。
3. AI 助手不出现在底部导航中。
4. AI 对话页必须显示当前模式。
5. 记账模式发送内容必须返回账单草稿，不得直接创建账单。
6. 助手模式发送图片不得默认按账单处理。
7. 助手模式开启“本条按账单处理”后，仅本次消息按账单解析。
8. 用户选择图片后，可以继续输入文字，再一起发送。
9. Agent 创建、修改、删除账单必须展示确认卡片。
10. 删除账单必须二次确认。
11. 从 AI 记账入口进入对话页时默认记账模式。
12. 从助手入口进入对话页时默认助手模式。
13. 从普通 + 进入时不得进入 AI 对话页。

最终建议你现在就定这个方向：**不要再找一个新的 Agent 悬浮入口，而是把 Agent 降为“稳定的二级入口”，把风险控制放到对话页模式和确认卡片里。**
这样普通记账体验不变，AI 记账用户有路径，Agent 用户也有稳定入口，后续工具增加也不会把首页挤乱。
