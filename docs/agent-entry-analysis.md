# Agent 入口信息架构分析

## 一、核心矛盾

这个问题表面上是"按钮放哪里"，实际上是三组矛盾的叠加：

**矛盾 1：高频无副作用 vs. 低频有副作用**

手动记账是每天多次、秒级完成的操作。Agent 查询是偶尔使用、多轮对话的操作。两者对"速度"和"防误操作"的要求截然相反。任何让记账变慢的方案都不可接受，任何让 Agent 操作不可控的方案也有风险。

**矛盾 2：三种功能的本质差异**

| 维度 | 手动记账 | AI 对话记账 | Agent |
|------|---------|------------|-------|
| 操作性质 | 写入（有副作用） | 写入（有副作用） | 读+写（工具调用） |
| 交互模式 | 表单，一次性 | 对话，单轮 | 对话，多轮 |
| 输入载体 | 文字/语音/图片 | 文字/语音/图片 | 文字/语音/图片 |
| 结果确认 | 必须确认 | 必须确认 | 视工具而定 |
| 使用频率 | 极高 | 高 | 中低 |

注意：AI 对话记账和 Agent 共享同一个聊天 UI，输入载体也完全相同。唯一的区别是"这条消息走哪条管线"。这意味着它们本质上是**同一个聊天页面的两种路由模式**，而不是两个独立功能。

**矛盾 3：不使用 AI 的用户 vs. 使用 AI 的用户**

如果把 Agent 提升到一级入口，不用 AI 的用户会觉得应用变了味。如果把 Agent 藏得太深，AI 用户找不到。这个矛盾要求方案必须对非 AI 用户**完全透明**。

**我的判断：三种功能不需要三个独立入口。**

手动记账和 AI 对话记账的区别仅在于输入管线，用户不需要知道这个技术差异。Agent 和记账的区别在于消息路由，但它们共享 UI、输入方式和上下文。因此，正确的抽象是：

- **一个记账入口**（"+"按钮，保持最高优先级）
- **一个统一的聊天页面**（内含记账模式和 Agent 模式的切换）

## 二、四种信息架构方案

### 方案 A：工具栏入口 + 统一聊天页

**结构：**
```
底部导航：账单 | 统计 | [+] | 资产 | 设置
"+" → 记账（传统表单 或 AI 对话记账，取决于用户设置）
主页面工具栏右侧 → Agent 图标按钮（仅 AI 用户可见）
Agent 图标 → 打开聊天页的 Agent 模式
聊天页内 → 顶部模式切换器（记账 / 助手）
```

**入口流程：**
- 记账：点击 "+" → 直接进入记账（零额外步骤）
- Agent：点击主页面工具栏 Agent 图标 → 进入聊天页 Agent 模式
- Agent 内记账：点击工具栏 "记账" 按钮 → 下一条消息走记账管线

**优点：**
- 记账零额外步骤，完全不受影响
- Agent 入口清晰但不抢视觉焦点（工具栏图标 vs FAB）
- 非 AI 用户完全看不到 Agent 入口
- 不改变底部导航结构
- 聊天页内模式切换直观

**缺点：**
- Agent 入口在工具栏，不如 FAB 显眼
- 新用户可能不知道工具栏图标的作用
- 主页面工具栏空间有限

**误操作风险：** 低。记账和 Agent 入口物理分离，不会混淆。
**学习成本：** 低。工具栏图标是 Android 标准交互。
**实现复杂度：** 低。删除 fab_agent，添加工具栏图标，修改聊天页模式切换。

---

### 方案 B：长按 "+" 呼出快捷菜单

**结构：**
```
底部导航：账单 | 统计 | [+] | 资产 | 设置
单击 "+" → 记账（传统 或 AI 对话记账）
长按 "+" → BottomSheet 快捷菜单：
  - 📝 记一笔（默认高亮）
  - 🤖 AI 助手（仅 AI 用户可见）
聊天页内 → 顶部模式切换器
```

**入口流程：**
- 记账：单击 "+" → 直接进入（零额外步骤）
- Agent：长按 "+" → 选择 "AI 助手" → 进入 Agent 模式
- Agent 内记账：同方案 A

**优点：**
- 记账零额外步骤
- 长按菜单是 Android 常见交互（通知栏快捷方式、桌面图标快捷方式）
- 不增加任何常驻 UI 元素
- Agent 入口隐藏得很好，不影响非 AI 用户

**缺点：**
- 长按是**隐藏交互**，可发现性差
- 用户可能永远不知道长按能呼出菜单
- 手指需要长按约 500ms，有轻微延迟
- 与部分手机的系统手势可能冲突（如长按触发语音助手）

**误操作风险：** 低。长按需要明确的持续触摸。
**学习成本：** 中。长按菜单不是所有用户都知道的交互。
**实现复杂度：** 低。

---

### 方案 C：聊天页会话抽屉内入口

**结构：**
```
底部导航：账单 | 统计 | [+] | 资产 | 设置
"+" → 记账（传统 或 AI 对话记账）
聊天页右侧抽屉 → 顶部有两个标签：记账会话 | 助手会话
切换到 "助手会话" → 自动进入 Agent 模式
新建会话按钮 → 弹出选择：新建记账会话 / 新建助手会话
```

**入口流程：**
- 记账：点击 "+" → 直接进入
- Agent：进入聊天页 → 打开右侧抽屉 → 切换到 "助手会话" 标签 → 选择或新建会话
- Agent 内记账：同方案 A

**优点：**
- 记账零额外步骤
- 不增加任何主页 UI 元素
- 会话管理自然地集成了 Agent 入口
- 符合聊天应用的常见模式（如微信的"文件传输助手"入口在联系人列表里）

**缺点：**
- Agent 入口需要 3 步操作（进入聊天 → 打开抽屉 → 切换标签）
- 用户必须先进入记账聊天页才能到达 Agent
- 如果用户只想用 Agent，必须先经过记账入口
- 右侧抽屉已经有会话列表，再加标签可能显得拥挤

**误操作风险：** 极低。
**学习成本：** 中。需要理解会话分类。
**实现复杂度：** 中。需要修改会话抽屉 UI。

---

### 方案 D：主页 Agent 小图标（替代当前 FAB）

**结构：**
```
底部导航：账单 | 统计 | [+] | 资产 | 设置
"+" → 记账（不变）
主页右下角 → 小型 Agent 图标按钮（非 FAB，更紧凑）
图标 → 打开聊天页 Agent 模式
聊天页内 → 模式切换器
```

**入口流程：**
- 记账：点击 "+" → 直接进入
- Agent：点击右下角小图标 → 进入 Agent 模式
- Agent 内记账：同方案 A

**优点：**
- 记账零额外步骤
- Agent 入口始终可见（对 AI 用户）
- 比当前的 FAB 更紧凑，视觉冲突更小

**缺点：**
- 仍然有一个常驻的悬浮元素
- 在资产页面可能与"新增资产"按钮冲突
- 小图标的可点击区域可能不够友好
- 本质上是当前方案的小幅改进，没有根本解决视觉层次问题

**误操作风险：** 中。两个悬浮按钮距离近时可能误触。
**学习成本：** 低。
**实现复杂度：** 低。

## 三、方案对比矩阵

| 维度 | A 工具栏 | B 长按 | C 抽屉 | D 小图标 |
|------|---------|--------|--------|---------|
| 记账额外步骤 | 0 | 0 | 0 | 0 |
| Agent 入口步骤 | 1 | 2 | 3 | 1 |
| 非 AI 用户影响 | 无 | 无 | 无 | 无 |
| 可发现性 | 高 | 低 | 中 | 高 |
| 视觉冲突 | 无 | 无 | 无 | 低 |
| Agent 可达性（从主页） | 1步 | 2步 | 需先到聊天页 | 1步 |
| 符合 Android 规范 | ✅ | ✅ | ✅ | ⚠️ |
| 扩展性 | 好 | 一般 | 好 | 差 |
| 实现复杂度 | 低 | 低 | 中 | 低 |

## 四、四类用户分析

**完全不用 AI 的用户：**
- 所有方案对此类用户均无影响（Agent 入口隐藏）
- 但方案 A/B/C 中，如果用户未来想尝试 AI，发现入口的方式不同
- 方案 A 最好：工具栏图标自然可见，点击后引导配置

**只使用 AI 记账的用户：**
- 所有方案保持 "+" → AI 对话记账的路径不变
- 此类用户可能偶尔想用 Agent 查统计，方案 A 的工具栏入口最方便

**经常使用 Agent 的用户：**
- 方案 A 最好：1 步从主页到达 Agent
- 方案 B 可以接受但有隐藏交互的不便
- 方案 C 步骤太多，对高频 Agent 用户不友好

**偶尔使用 Agent 的普通用户：**
- 此类用户不会记住隐藏交互
- 方案 A 最好：图标可见，点击即达
- 方案 B 的长按菜单可能永远不被发现

## 五、推荐方案：方案 A（工具栏入口 + 统一聊天页）

**为什么方案 A 比其他方案更合适：**

1. **记账零影响**："+"按钮行为完全不变，非 AI 用户体验零变化。
2. **Agent 可发现**：工具栏图标是可见的、标准的 Android 交互，不需要用户"学习"。
3. **一步到达**：从主页到 Agent 只需 1 次点击。
4. **视觉层次正确**：Agent 是工具栏上的一个图标，不会与"+"争夺视觉焦点。
5. **扩展性好**：未来增加更多入口（如快捷方式、通知等）不会与现有结构冲突。
6. **实现简单**：删除 fab_agent，添加工具栏图标，改进聊天页模式切换。

**为什么不选其他方案：**
- B：长按是隐藏交互，可发现性太差。"长按"在移动端的认知成本高于桌面端。
- C：3 步到达 Agent 对高频用户不友好，且必须先进入记账聊天页。
- D：本质是当前方案的小幅改进，没有解决根本问题。

## 六、推荐方案的详细交互流程

### 6.1 首页入口

**"+"按钮行为（不变）：**
- 未配置 AI：打开传统记账表单（BottomSheetDialog）
- 已配置 AI 且设置为 AI 模式：打开 ChatActivity，MODE_ACCOUNTING
- 已配置 AI 且设置为传统模式：打开传统记账表单

**Agent 入口（新增）：**
- 位置：主页面 Toolbar 右侧，设置图标旁边
- 形式：图标按钮（🤖 或 ✨），紧凑的 IconButton
- 可见性：仅当 `Prefs.isAiConfigured()` 为 true 时显示
- 点击行为：打开 ChatActivity，MODE_AGENT，创建新会话
- Tooltip：首次出现时显示简短提示 "AI 助手"

### 6.2 聊天页模式切换

**Toolbar 改造：**

当前 Toolbar 结构：
```
[返回] [AI头像] [AI名称] [模型副标题] [切换按钮] [更多菜单]
```

改造后：
```
[返回] [模式切换器: 记账|助手] [模型副标题] [记账快捷按钮*] [更多菜单]
```

**模式切换器：**
- 形式：Segmented Button（Material Design 3 标准组件）
- 两个选项：「记账」和「助手」
- 当前选中项高亮
- 切换后，当前会话的模式立即改变（不需要新建会话）
- 切换时保存当前会话状态

**记账快捷按钮（仅在 Agent 模式下显示）：**
- 位置：模式切换器右侧
- 形式：文字按钮 "记账"，点击后变为 "记账 ✓"
- 功能：标记下一条消息走记账管线
- 发送后自动恢复为 Agent 模式
- 这是现有 `sendAsAccounting` 功能的保留

### 6.3 模式切换的行为细节

**切换到记账模式：**
- 输入提示变为："输入账单内容..."
- 空状态显示：记账示例提示
- 发送的消息走记账管线
- 图片走账单识别
- 语音走账单识别

**切换到 Agent 模式：**
- 输入提示变为："输入消息或问题..."
- 空状态显示：Agent 示例提示（查询统计、管理账单等）
- 发送的消息走 Agent 管线
- 图片作为上下文发给 LLM
- 语音转文字后发给 Agent

**模式持久性：**
- 模式切换是**会话级别**的持久状态
- 切换到 Agent 模式后，用户继续聊天都走 Agent 管线，直到主动切回记账
- 退出聊天页再进入，恢复上次的模式状态
- 新建会话时，默认模式取决于进入方式（从"+"进入→记账，从工具栏 Agent 图标进入→Agent）

### 6.4 图片选择和图文发送

**记账模式：**
- 点击图片按钮 → 选择图片 → 图片预览显示在输入框上方
- 可以继续输入文字
- 点击发送 → 图片+文字一起走账单识别管线
- 行为与现有完全一致

**Agent 模式：**
- 点击图片按钮 → 选择图片 → 图片预览显示在输入框上方
- 可以继续输入文字
- 点击发送 → 图片+文字一起发给 Agent（图片作为 vision 内容）
- Agent 可以看到图片并进行对话

**Agent 模式下的"记账"快捷按钮：**
- 用户选择图片后，点击"记账"按钮
- 发送 → 图片+文字走账单识别管线
- 发送后自动恢复 Agent 模式

### 6.5 未配置 AI 时的处理

**主页：**
- Agent 工具栏图标不显示
- "+"按钮行为不变（打开传统记账）
- 底部导航不变

**用户点击聊天相关功能时（如有其他入口）：**
- 弹出引导对话框："需要先配置 AI 服务才能使用此功能"
- 提供"去配置"按钮，跳转 AiProviderSetupDialog
- 提供"取消"按钮

### 6.6 记账前的确认策略

**记账模式下（无论文字、语音、图片）：**
- AI 返回账单草稿 → 显示确认卡片
- 用户确认 → 保存账单
- 用户修改 → 编辑后保存
- 用户取消 → 不保存

**Agent 模式下使用"记账"快捷按钮：**
- 同上，走相同的确认流程
- 确认卡片在聊天流中显示

**Agent 模式下通过工具调用创建账单（如用户说"帮我记一笔午饭30元"）：**
- Agent 调用 create_bill 工具 → 工具返回结果
- 结果显示在聊天中，包含账单详情
- 这是 Agent 工具调用的结果，不是直接记账，用户可以在聊天中看到完整记录

### 6.7 返回和状态恢复

**按返回键：**
- 关闭聊天页，返回主页
- 会话状态保存（当前模式、输入框内容、待发送图片）

**再次进入聊天页：**
- 从"+"进入 → 恢复上次的记账会话（如有）
- 从 Agent 图标进入 → 恢复上次的 Agent 会话（如有）
- 如果没有历史会话，创建新会话

**会话抽屉（右侧）：**
- 记账会话和 Agent 会话在同一列表中
- 用不同的图标或标签区分（如记账用💰，助手用🤖）
- 点击任意会话 → 切换到该会话，自动设置对应模式

### 6.8 会话抽屉的改造

**新建会话按钮：**
- 保持现有的 "+" 按钮
- 点击后根据当前模式创建对应类型的新会话

**会话列表：**
- 每个会话项显示：图标（💰/🤖）+ 标题 + 最后消息预览 + 时间
- 记账会话和 Agent 会话混合排列（按时间排序）
- 或者提供顶部标签切换：全部 | 记账 | 助手

**建议：混合排列 + 图标区分**
- 简单直接，不需要额外的标签切换
- 用户通过图标一眼就能区分会话类型
- 点击会话自动切换到对应模式

**主页工具栏 Agent 图标：**
- 图标：🤖（或 Material Symbols 的 `smart_toy`）
- Content Description："AI 助手"
- Tooltip（首次）："打开 AI 助手，查询数据或管理账单"

**聊天页模式切换器：**
- 选项 1："记账"
- 选项 2："助手"

**记账模式输入提示：**
- 文字输入框 Hint："输入账单内容..."
- 语音提示："说出账单内容"

**Agent 模式输入提示：**
- 文字输入框 Hint："输入消息或问题..."
- 语音提示："说出你的问题"

**Agent 模式下的记账快捷按钮：**
- 默认状态："记账"

- 激活后输入提示："输入账单内容，发送后自动恢复对话模式"

**Agent 空状态提示：**
- 标题："有什么可以帮你的？"
- 示例：
  - "这个月花了多少钱？"

- 标题："开始记账"

  - "午饭 35 元"
  - "打车 20 元"
  - 或直接拍照/语音

**会话列表标签：**
- 记账会话图标：💰
- Agent 会话图标：🤖
- 模式标签（可选）："记账" / "助手"（小字灰色）

## 八、现有设计的保留与删除

**应删除：**

| 项目 | 原因 |
|------|------|
| `fab_agent`（Agent FAB） | 被工具栏图标替代，消除视觉冲突 |
| `AI_ENTRY_MODE` 设置中的 Agent 相关选项 | Agent 入口不再通过"+"控制 |
| `AI_ENTRY_MODE_CHAT` 和 `AI_ENTRY_MODE_TRADITIONAL` 的区分逻辑 | 可以简化：有 AI → 聊天页，无 AI → 传统表单。或者保留这个设置但只控制"+"的行为 |
| `btn_switch_model` 在记账模式下显示"切换"的行为 | 改为模式切换器，不再用这个按钮切换模型 |

**应保留：**

| 项目 | 原因 |
|------|------|
| `sendAsAccounting` 机制 | Agent 模式下的"记账"快捷按钮，功能正确 |
| `ChatInputRouter` 的三种路由 | 架构合理，保持不变 |
