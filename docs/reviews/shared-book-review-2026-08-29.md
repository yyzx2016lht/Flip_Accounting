# 共享账本优化总结

> 更新日期：2026-08-29
> 实际同步服务：坚果云 WebDAV
> 当前产品边界：每个共享账本 1–5 位成员；现在只使用 2 位成员也完全适用

## 结论

本轮已经把共享账本从“创建时由邀请方预先指定两个人”调整为更清楚的成员模型：

1. 新共享账本创建后可以只有创建者一人。
2. 只有创建者能逐个创建邀请席位，最多 5 位成员。
3. 被邀请者加入时填写自己的成员名称，邀请者不再替对方命名。
4. 新邀请有待加入/已领取状态，不能重复领取；待加入邀请可以撤销并释放名额。
5. 非创建者不再显示或生成反向邀请，因此不会把创建者身份分享出去。
6. 已有两人共享账本继续使用，不做数据库迁移，也不主动改写远端成员数据。
7. 换机统一走“加密备份 → 新设备恢复 → 保留原身份并重新连接”，不会占用新的成员名额。

同时修复了此前审查中影响较大的同步正确性问题：预算冲突不收敛、预算与 outbox 非原子、纯拉取失败假报成功、远端积压只处理 50 条、详情编辑绕过共享协议、批量清理绕过 tombstone，以及共享账单恢复后只留在本机等。

## 最终成员与邀请规则

| 场景 | 当前行为 |
| --- | --- |
| 新建共享账本 | 只创建 `joinOrder=1` 的创建者 |
| 邀请新成员 | 创建者逐个创建 `joinOrder=2..5` 的空席位 |
| 成员名称 | 创建者只填写自己的名称；其他成员加入时自行填写 |
| 最大人数 | 创建者加其他成员合计最多 5 人 |
| 邀请领取 | 新邀请只能领取一次，并使用坚果云 ETag 条件更新降低并发抢占风险 |
| 撤销邀请 | 只允许撤销尚未领取的新版邀请 |
| 再次发送 | 只对仍为空的待加入席位显示发送入口 |
| 普通成员权限 | 可以查看详情、改自己的名称、同步、更新密码、退出；不能邀请或解散 |
| 创建者权限 | 在普通成员能力上增加邀请、撤销邀请和解散 |

共享详情现在显示坚果云账号（脱敏）、本机角色、成员列表与人数、待加入席位、最近同步结果、错误和待上传数量，并提供立即同步与更新坚果云应用密码的入口。

## 对现有共享账本的兼容策略

这次修改刻意没有引入 Room schema 变化。

- 远端 manifest 仍是 schema v1。
- `invitedAt`、`joinedAt` 是可选字段；旧 manifest 缺少它们时按旧数据读取。
- 原有两成员 manifest 仍通过校验。
- 原有合法的成员 2 邀请仍能解码和加入，加入者会用自己填写的名称覆盖旧邀请者预填名称。
- 本地 `shared_ledger`、`shared_member` 等表没有新增列，升级时不需要迁移或重建。
- 对现有账本，只有用户主动邀请、改名或更新密码时才会写远端 manifest。
- 出于安全原因，指向 `joinOrder=1` 创建者身份的普通邀请会被拒绝；这是对原身份克隆漏洞的封堵。

需要注意：只有新版客户端认识“创建者一人起步”和新版邀请领取字段，因此新建的一人共享账本应由升级后的客户端加入。旧版客户端继续同步原有两人账本不受本地数据库迁移影响。

## 本轮已修复的问题

### 1. 身份与邀请

- 修复成员 B 反向导出创建者 A 身份的问题。
- service 层和 UI 层都限制只有创建者能邀请。
- 普通邀请只能指向成员席位 2–5，不能指向创建者。
- 新邀请写入时间和领取时间；并发更新优先使用坚果云返回的 ETag/`If-Match`。
- 待加入邀请可以撤销；已经领取或旧版成员不能被误删。
- 成员改名只修改自己的稳定 memberId 对应名称。

### 2. 共享详情与恢复入口

- 已共享账本入口直接打开共享详情，不再先弹出错误邀请。
- 增加角色、成员、同步健康、待上传和坚果云账号信息。
- 增加更新坚果云应用密码，并在保存前验证远端 Book UUID 和本机成员身份。
- “退出并删除本地副本”中的账单、预算、聊天记录与共享关系改为单一数据库事务。
- 首次加入若远端同步失败，会明确显示“已加入但首次同步失败”，并安排完整重试，不再假报全部完成。
- 加密备份会保存共享账本 UUID、本机 `memberId`、成员资料、离线 outbox 和坚果云应用密码；换机恢复时保留原 `memberId`，同时生成新的 `deviceId`。
- 恢复界面把“保留原身份并重新连接”作为换机推荐项；普通无共享数据的备份不再误弹共享恢复选项。
- 恢复前会校验每个共享账本都具备本机成员记录和坚果云凭据，再访问远端确认账本未解散、UUID 一致且原成员仍存在。资料不完整时只允许恢复为本地副本。
- 备份完成后会根据实际密封归档的模块清单提示“可恢复原共享成员身份”或“共享连接资料不完整”，避免把不完整备份误当成换机备份。
- 修复同一天连续点击备份后只剩一份的问题：本地和坚果云现在按设备、按模式保留最近版本（轻量 10 份，完整/自定义 3 份），同时继续保留日、周、月长期版本。
- 本地恢复入口改为版本卡片列表：以备份类型、时间、设备和大小为主信息，标记最新版本；原始文件名降为辅助信息，多版本时在弹窗内滚动。

### 3. 多成员预算

- 个人预算分配由固定双输入框改为 2–5 位已加入成员的动态列表。
- 空的邀请席位不会参与预算分配。
- 没填金额的成员均分剩余额度；全部留空时保留原来的共享总预算行为。
- 旧双人预算 API 和成员额度 JSON 保持兼容。
- 预算实体、sync operation、sync queue 现在在同一 Room transaction 中提交；同步调度在提交成功后触发。

### 4. 同步结果和冲突收敛

- Worker 会统计失败账本；即使上传队列为 0，纯拉取失败也会 retry。
- 有上次同步错误的账本会绕过 quiet period，尽快做完整同步。
- 移除“只处理前 50 个远端文件却写入成功时间”的行为；一轮完整 drain 后才标记成功。
- delete 被定义为永久 tombstone，和同 revision update 的到达顺序无关。
- full sync 会幂等重放已知 tombstone，修复旧客户端记录了删除却未物化的问题。
- 账单快照不会覆盖已经存在 tombstone 的实体，避免已删除账单复活。

### 5. 账单写入、恢复与批量清理

- 账单详情保存改走 `BillMutationService`，统一校验所有者、revision 和 outbox。
- 退款与来源账单的联动编辑会校验双方所有者，并为两条记录分别产生共享更新。
- 只读的退款来源解析不再顺手 raw update 数据库。
- 共享账单从回收站恢复时创建新的 shared identity，并发送 create operation；不会复用已经 tombstone 的旧 identity。
- 备份页按日期、按账本和全部清理会先对整批共享账单做所有者预检，再在一个事务里写 tombstone 和删除实体。
- 普通批量删除也改为先全量预检、后单事务提交，避免删到一半才发现包含他人账单。
- 覆盖恢复在存在活跃共享账本时禁止恢复账单/预算；合并恢复也会拒绝写入同名活跃共享账本，避免共享实体与运行时日志脱节。

### 6. 坚果云边界

- 新建共享账本固定使用 `https://dav.jianguoyun.com/dav/`，创建界面不再暴露任意 WebDAV 地址。
- 现有共享账本仍保留原连接字段，不会在升级时被改写。
- 应用密码继续只保存在本机安全存储中，不写进邀请文本。

## 仍建议继续优化

以下项目没有必要阻挡现在的 2 人使用或 1–5 人邀请，但值得作为下一阶段：

1. **真实坚果云双机故障测试**：覆盖同时领取邀请、断网、401、429、503、进程被杀、ETag 缺失和弱 ETag。
2. **逻辑 checkpoint**：当前完整同步不再截断 50 条，但仍需扫描远端历史，历史很大时首次同步会变慢；下一步应加入高水位和压缩 checkpoint。
3. **创建/加入 saga**：远端 manifest、Room 和本机凭据仍跨三个存储系统；应增加 provisioning 状态和幂等补偿，处理中途杀进程。
4. **已加入成员移除与设备失窃**：目前只支持撤销未领取邀请。正常换机已由加密备份恢复覆盖，但主动踢出已加入成员、旧设备遗失后的凭据轮换仍需单独机制。
5. **旧邀请领取状态**：旧 manifest 没有 `invitedAt/joinedAt`，无法可靠判断历史邀请是否已领取，所以详情页不会重新暴露旧成员邀请。
6. **共享账本名称语义**：当前本机 Book 名和远端共享名仍可不同；需要决定改名是本机别名还是同步给所有成员。
7. **活动与冲突记录**：增加“谁在何时新增、编辑、删除了什么”、坏远端文件和人工修复记录。
8. **超大历史压力**：远端枚举仍有 10,000 项保护上限；checkpoint 完成前应对大历史给出可见告警。

## 建议的坚果云验收清单

发布前至少用两台真实设备验证：

1. A 新建共享账本，未邀请时能独立记账和同步。
2. A 连续邀请 B、C、D、E；第 6 个成员被拒绝。
3. B 加入时自行改名，A 同步后看到 B 的名字；B 看不到邀请和解散入口。
4. 同一新版邀请在两台设备同时领取，只允许一台成功。
5. A 撤销未领取邀请后，旧链接失效且名额可再次使用。
6. 原有两人共享账本升级后账单、预算、成员和邀请读取正常。
7. 两端离线分别 update/delete 同一预算，恢复网络后都保持删除。
8. 制造 51 条以上远端操作，单次完整同步全部处理后才更新成功时间。
9. 使用错误应用密码触发失败，再从共享详情更新密码并恢复同步。
10. 共享账单详情编辑、回收站恢复、备份页批量清理都能在另一端得到一致结果。
11. A 创建加密备份，确认提示“可在新设备恢复原共享成员身份”；在新设备恢复时选择“保留原身份并重新连接（推荐·换机）”。
12. 新设备恢复后确认成员名称和成员数不变、能拉取 B 的新账单，并能把新账单同步到 B；随后停止旧设备继续记账。
13. 用缺少共享连接资料的备份恢复时，确认应用不会提供重新连接，只允许恢复为本地副本。
