## 任务目标

## 项目背景

这是一个 Android 记账应用，当前项目中 UI 文案分散在以下位置：

- `app/src/main/res/values/strings.xml`
- `app/src/main/res/values/arrays.xml`
- `app/src/main/AndroidManifest.xml`
- `app/src/main/res/layout/**/*.xml`
- `app/src/main/res/menu/**/*.xml`
- `app/src/main/java/**/*.kt`
- `app/src/main/java/**/*.java`

注意：当前项目里有大量用户可见文本并没有放在 `strings.xml`，而是直接硬编码在 XML、Manifest 和 Kotlin 代码里。整改时不要只改 `strings.xml`。

## 你的核心任务

### 第一步：修复高风险问题

优先修复以下问题：

- `AndroidManifest.xml` 中的乱码标题

### 第三步：重点重写高频页面文案

请优先处理以下页面：

1. AI 功能页
2. 聊天页

4. 分类管理
5. 备份与恢复

这些页面的文案要求：

- 更强调“能做什么”“是否联网”“是否收费”“是否更快/更准”
- Toast、Dialog、空状态、按钮文案要自然统一

### 第四步：文案资源收口

请尽量把用户可见文案迁移到资源文件中，优先收口以下内容：

- `AndroidManifest.xml` 里的 `android:label`
- `layout` 中的 `android:text`、`android:hint`
- `menu` 中的 `android:title`
- Kotlin/Java 里的 `Toast`、`Dialog title`、`Dialog message`、按钮文案、空状态文案

注意：

- 不要求一步把全项目所有硬编码全部消灭
- 但至少要把你本次改动涉及到的用户可见文案改为资源引用，避免继续扩大硬编码

## 文案风格规则

请严格遵守以下规则：

1. 面向用户，不面向开发者。
2. 说明“作用”和“代价”，少说“实现方式”。
3. 用词简洁，不堆术语。
4. 同类按钮统一：
   - `取消`
   - `保存`
   - `删除`
   - `确认删除`
   - `去设置`
   - `去开启`
5. 同类状态统一：
   - 成功提示简短明确
   - 失败提示说明下一步
   - 空状态尽量自然，不要生硬
6. 避免这些表达：
   - `token`
   - `多模态`
   - `模型路由`
   - `核心模型未解锁`
   - 过于技术化的“接口级”说法
7. 可以保留 `Shizuku`、`API Key` 这类必要专有名词，但不要在主文案中高频堆砌；优先把它们放在次级说明里。

## 重点文案修改方向

以下是推荐修改方向，你可以据此落地：

### AI 功能页

- `AI 智能功能` 可简化为 `AI 功能`
- `AI 核心模型未解锁` 优先改为 `AI 功能未配置` 或 `AI 服务尚未配置`
- `请向开发者索要配置密钥，点此输入。` 优先改为 `请先输入 API Key，完成后即可使用 AI 功能。`
- `会多轮次使用模型进行分类，使用 token 更多。` 优先改为 `识别更细，但耗时更长、消耗更多额度。`
- `本地 ML Kit` 优先改为 `本地识别`
- `多模态云端` 优先改为 `云端识别`

### 设置中心 / 分类管理

- 区分 `设置中心` 和 `分类管理`，不要混为同一标题
- `点击设置名字和头像` 优先改为 `点击编辑头像和昵称`
- `管理一级分类、二级分类与排序` 优先改为 `管理分类、子分类和显示顺序`

### 聊天页

- `AI 瀵硅瘽璁拌处` 修正为 `AI 对话记账`
- `你在 AI 对话里发送语音前，需要先到设置中心开启“语音记账”功能。`
  可改为
  `要在 AI 对话中发送语音，请先到设置中心开启“语音记账”。`
- 图片、语音、处理中、识别中等中间态文案统一语气
